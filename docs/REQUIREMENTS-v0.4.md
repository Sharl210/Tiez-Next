# Tiez-Next v0.4 需求规格

本文档把 11 项用户需求正式化，作为开发与验收的依据。每条需求给出：**现象/目标、验收条件、代码落点、约束**。

- 文档版本：v0.4-draft
- 来源：用户于 2026-09-22 提出的 11 项需求（原话见附录）
- 适用范围：Tiez-Next 自有版本（不涉及与原版 TieZ 的兼容；原版数据已由 v0.3.4 的一次性迁移处理）

---

## 术语

| 术语 | 含义 |
|---|---|
| **窗口置顶 / pin（窗口级）** | 剪贴板主窗口的 `always_on_top` + 不可夺焦状态，代号 `WINDOW_PINNED` |
| **条目固定（条目级）** | 某条剪贴板记录的 `is_pinned`，只影响排序与快捷键，与窗口状态无关 |
| **唤起屏** | 用户触发剪贴板窗口显示那一刻，鼠标/焦点所在的显示器 |
| **前向兼容** | 新版生成的数据能被旧版读取（旧版读新版不崩） |
| **后向兼容** | 旧版生成的数据能被新版读取（新版读旧版完整恢复） |

> **重要**：需求 1 中的「pin」指**窗口级**。经勘察两者代码零交叉（见 `docs/DEV-PLAN-v0.4.md` 附录 B）。

## R1 多显示器：窗口不跨屏跳变、不自动置顶、异屏点击不隐藏

### 现状（缺陷）
主副双屏环境，唤起剪贴板窗口后：
- (a) 鼠标焦点从一块屏移到另一块屏，窗口会**跟着跳过去**；
- (b) 窗口会**自动变成窗口置顶（pin）状态**；
- (c) 在另一块屏幕上点击会导致窗口被隐藏。

### 目标
- 窗口**始终保留在唤起时的原屏幕**，不随鼠标/前台窗口跨屏移动。
- **不自动**进入窗口置顶状态；窗口是否置顶只由用户显式操作决定。
- 在另一块屏幕上的点击操作**不隐藏窗口**；窗口状态（含 pin 与否）不受影响。

### 验收条件
1. 在屏 A 唤起窗口 → 鼠标移到屏 B 并点击 → 窗口仍在屏 A、位置不变、可见。
2. 上述过程中 `WINDOW_PINNED` 保持为用户设定值不变；UI 图钉图标不发生变化。
3. 窗口边缘贴近屏幕边界时**不得**自动置顶。
4. 用户显式点击图钉 → 仍能正常置顶/取消置顶（功能未被破坏）。
5. 点击窗口外（同一屏内）的既有隐藏行为**按既有设定保留**，不因本需求改变。

### 代码落点（已勘察）
| 位置 | 问题 |
|---|---|
| `src-tauri/src/app/window_manager.rs:123-190` | `follow_mouse` 支路按 `GetCursorPos` 鼠标位置落位 |
| `src-tauri/src/app/window_manager.rs:191-266` | `was_docked` 支路按 `active_center.unwrap_or(鼠标点)` 选屏 |
| `src-tauri/src/app/window_manager.rs:267-335` | else 支路发现不同屏就 `remap_fixed_window_position` 搬窗 |
| `src-tauri/src/app/setup.rs:861-866` | 贴边判定 `threshold = 5` |
| `src-tauri/src/app/setup.rs:907-936` | 贴边时自动 `WINDOW_PINNED.store(true)`（**唯一自动置顶路径**） |
| `src-tauri/src/app/hooks/mod.rs:446-457` | 全局鼠标钩子：点击距窗口超 5px 即隐藏 |
| `src-tauri/src/app/setup.rs:1338-1390` | 失焦 200ms 后隐藏 |

**关键耦合**：`window_manager.rs:169-171` 将窗口 clamp 在距屏边 **5px**，与 `setup.rs:801` 的 `threshold = 5` 完全重合——主副屏交界正是主屏的一条边缘，故窗口被摆到交界附近即被判"贴边"→ 自动置顶 → 隐藏。这解释了 (b) 与 (c) 的联动。

### 约束
- 不引入新的显示器轮询频率；不改变既有用户可配置项语义。

## R2 标签管理：分栏比例可记忆

### 现状
`TagManager.tsx` 的 `sidebarWidth` / `sidebarHeight` 为纯 `useState`（初值 130 / 180），拖动后可改变但**不持久化**，重新打开即复位。对比：同一文件的 `viewMode` 已用 `localStorage` 持久化（`TAG_MANAGER_VIEW_MODE_KEY`）。

### 目标
用户拖动标签标题与标签条目之间的分割后，**下次打开保持该比例**。

### 验收条件
1. 拖动分割线到任意位置 → 关闭并重新打开标签管理 → 分割位置与关闭前一致。
2. 竖排（`isStacked`）与横排两种布局**分别记忆**各自尺寸。
3. 自动折叠（`dragPos < 110` → `isCollapsed`）状态同样可记忆；折叠态下次打开仍为折叠。
4. 存储值非法/损坏时回退到默认值，不崩溃。

### 代码落点
`src/features/tag/components/TagManager.tsx:47-48`（state 定义）、`:96-135`（拖动逻辑）、`:22`（既有 localStorage 持久化范例）

### 约束
沿用既有 `localStorage` 方案（与该文件 `viewMode` 一致），不新增后端命令。

## R3 标签管理：所有分组可删除，且随功能关闭而隐藏

### 现状
`TagManager.tsx` **硬编码** `'sensitive'` 与 `'密码'` 为不可删：
- `:193` 重命名时特判
- `:209` 删除时直接 `return`（拒绝）
- `:392`、`:405` 隐藏其删除按钮

### 目标
- **所有分组都可删除**（含 `sensitive`、密码 等）。
- 内置分组应**随对应功能关闭而隐藏**（功能关闭 → 分组不显示）。
- **删除后不得出错**：任何分组被删后，标签管理、剪贴板主页面、筛选、粘贴等路径均正常工作。

### 验收条件
1. 删除任意分组（含内置）成功且无报错。
2. 删除后：该分组名下条目的 `entry_tags` 关联被清理；条目本身**不丢失**（只解除关联）。
3. 删除后刷新/重启，分组不复活。
4. 对被删分组执行筛选/搜索不报错（返回空结果）。
5. `sensitive` / 密码 对应功能关闭时，该分组不出现在列表中。

### 代码落点
`src/features/tag/components/TagManager.tsx:193/209/392/405`；后端标签命令 `src-tauri/src/app/commands/tag_color_cmd.rs`；表 `saved_tags` / `entry_tags`

### 约束
**这是破坏性操作**，须按 `desktop-release-crossbuild` skill 的「破坏性操作四层防护」处理：删除前明确提示影响范围（将解除 N 条条目的关联，条目本身保留）。

## R4 标签内条目可编辑（不论格式）

### 现状
标签内条目仅支持部分编辑能力（`editingItem` 存在但格式受限）。

### 目标
**每个标签里的条目都可编辑，不论格式**（纯文本 / HTML / 图片 / 文件 / 富文本 等）。

### 验收条件
1. 文本、代码、URL、富文本：可编辑正文。
2. 图片、文件：可编辑**元数据**（如备注、标题/显示名）——原始二进制不可改，但编辑入口对这些格式同样可用且不报错。
3. 编辑保存后，列表、搜索、粘贴均反映新内容。
4. 编辑不破坏 `content_type` 语义（例如不把图片变成文本）。

### 约束
「不论格式」的解释：**编辑入口对全部格式开放**；对二进制类内容，可编辑的是附加信息而非字节本身。此解释需在实现中向用户明示（UI 上对图片/文件隐藏"正文编辑"但保留备注等编辑）。

## R5 缺陷：图片被吞 / 链接变成网站标题

### R5.1 连续复制图片被吞

#### 现状（缺陷）
连续复制图片时，部分图片**未进入历史记录**（丢失）。

#### 已定位的可疑根因
`src-tauri/src/services/clipboard/mod.rs:544-571` 的内容去重：
- 把**文本哈希与图片字节哈希混入同一个 hasher**（`:556` 文本、`:560` 图片）；
- 判定条件为「哈希相同 且 距上次处理 < 2000ms」即跳过（`:564-569`）。

**风险**：两张**不同**图片在 2 秒内先后复制时，若其中任一张同时带有可读文本（或不带文本导致哈希构成不同），哈希可能碰撞/组合出相同值；更关键的是**图片哈希基于 `image.bytes`**，若采集时序上 `cached_image` 未及时更新（缓存复用），第二次会复用上次的字节 → 哈希相同 → **被误判为重复而跳过**。

#### 验收条件
1. 连续快速复制 N 张**不同**图片（间隔 < 2s）→ 全部进入历史记录，N 张都在。
2. 复制同一张图片两次（间隔 < 2s）→ 去重仍生效（只 1 条或不产生重复），既有行为不退化。
3. 图片与文本交替快速复制 → 两者都不丢。

#### 约束
修复不得通过「直接关闭去重」实现——去重是既有功能（`settings.deduplicate`）。需修正哈希构成与缓存时序。

### R5.2 链接变成网站标题

#### 现状（缺陷）
复制链接后内容**自动变成网站标题**。导致之后粘贴——无论右键「粘贴为纯文本」还是正常单击——都只有标题纯文本，**看不到原始链接**。

#### 勘察结论
后端**未发现**主动抓取网页标题的代码（全库无 `og:title` / `fetch_title` / `<title>` 解析，除 `web_ui.rs:332` 的静态 HTML 模板）。

**因此最可能的来源**：浏览器复制链接时同时写入多种剪贴板格式（`CF_UNICODETEXT` = 标题、`CF_HTML` = `<a href="URL">标题</a>`）。本项目若优先取 HTML/富文本并**将可见文本（标题）落库为 `content`**，而 URL 未单独保留，就会产生此现象。

#### 待确认（实现前必须验证）
1. 数据库里该条记录的 `content`、`preview`、`html_content`、`content_type` 实际值是什么？
2. 原始 URL 是否仍在 `html_content` 的 `href` 中？（若在，可解析还原；若已被剥离，则需改采集逻辑）
3. 「粘贴为纯文本」走哪个后端函数？（`paste_as_plain`？）为何也拿不到 URL？

#### 验收条件
1. 从浏览器复制一个链接 → 历史记录中**可获取原始 URL**（至少一处保留完整 URL）。
2. 粘贴（正常单击）→ 得到链接（而非仅标题）。
3. 右键「粘贴为纯文本」→ 得到**纯文本形式的 URL**（`https://...`），不是标题。
4. 若来源同时在 HTML 中提供了锚文本，标题**可作为附加信息保留**（如作为备注/预览），但不得取代 URL。

## R6 标签条目支持备注，并在两处显示

### 目标
- 标签条目可添加**备注信息**。
- 备注可在**标签管理**与**剪贴板主页面**的条目上显示。

### 验收条件
1. 任一格式的条目均可添加/编辑/清空备注。
2. 标签管理列表中该条显示备注。
3. 剪贴板主页面该条显示备注。
4. 备注持久化，重启后仍在。
5. 备注长度有合理上限（建议 2000 字符）且不破坏布局（超长截断 + 悬浮/tooltip 显示全文）。

### 数据模型
需在 `clipboard_history` 新增列（当前 schema 版本 = 10，新增 migration 版本 11）：
```
note TEXT NOT NULL DEFAULT ''
```

### 约束
- 兼容性：新列必须有默认值，保证旧库升级可用（后向兼容，见 R8.4）。

## R7 标签管理中的粘贴计入历史

### 现状
在标签管理里点击条目执行粘贴**不产生**新历史记录。

### 目标
标签管理中的粘贴**也算作一次粘贴/复制记录**，可在剪贴板主页面看到，并**成为最新条目**。

### 验收条件
1. 在标签管理点击条目粘贴 → 剪贴板主页面顶部出现该条目（或一条新记录）。
2. 该条目的时间戳为当前时间（体现"最新"）。
3. 与 R8 兼容性要求一致：该记录能被正常导出/导入。
4. 不产生重复刷屏（连续粘贴同一内容按既有去重规则处理）。

### 待确认
「成为最新条目」的语义有两种实现，需在实现时择一并保持一致：
- **(A) 提升既有条目**：把该条目 `timestamp` 更新为当前时间（不新增行，`use_count` +1）。
- **(B) 新增一条**：插入新记录。

**建议 (A)**：与既有 `use_count` 机制一致，避免历史膨胀。若用户期望 (B) 则调整为 (B)。

## R8 备份导出 / 导入恢复（zip，完全恢复）+ 双向兼容

### R8.1 备份导出
- 格式：**zip**
- 内容：**全部数据**
- 必须包含（按数据目录实勘，见 `docs/DEV-PLAN-v0.4.md` 附录 A）：
  - 数据库文件 `clipboard.db`（含 WAL 一致性快照）
  - 附件目录 `attachments/`
  - 表情收藏 `emoji_favorites/`
  - 自定义背景
  - 自定义数据路径标记 `datapath.txt`
  - 其余运行时可重建的缓存**可不含**，但须在清单中说明

### R8.2 导入恢复
- **「导入恢复就是完全恢复」**：导入后，剪贴板历史、标签、标签关联、备注、附件、表情收藏、自定义背景、设置项全部与导出时一致。
- 验收条件（**逐项比对**）：
  1. 条目总数一致
  2. 每条 `id` / `content` / `content_type` / `timestamp` / `use_count` / `is_pinned` / `tags` / `note` 一致
  3. `entry_tags` 关联数一致
  4. `saved_tags` 数量与颜色一致
  5. `attachments/` 文件数与逐个校验和一致
  6. `emoji_favorites/` 一致
  7. 自定义背景文件一致
  8. 设置项关键键值一致

### R8.3 导出格式的元数据
zip 内必须含清单文件（建议 `manifest.json`）：
```json
{
  "app": "Tiez-Next",
  "format_version": 1,
  "schema_version": 11,
  "app_version": "0.4.0",
  "exported_at": "<ISO8601>",
  "platform": "windows",
  "counts": { "entries": 0, "tags": 0, "attachments": 0 },
  "files": [ { "path": "clipboard.db", "size": 0, "sha256": "..." } ]
}
```

### R8.4 双向兼容（长期规则）
> **此为本项目长期约束**：后续所有版本必须同时保持**前向兼容**与**后向兼容**。

- **后向兼容**（新版读旧版包）：新版必须能导入**任何历史版本**导出的 zip。做法：以 `format_version` 为界，旧版本包由升级路径处理；数据库 schema 变更一律走 `schema_migrations` 增量迁移，新列必须有默认值。
- **前向兼容**（旧版读新版包）：旧版导入更高 `format_version` 的包时，**必须安全拒绝并给出明确提示**，绝不部分导入导致数据损坏；能识别的字段应尽力恢复。
- **实现要求**：
  1. 导入前校验 `format_version` 与 `schema_version`；高于当前支持范围 → 拒绝并提示「此备份由更新版本创建，请升级后再导入」。
  2. 低版本包 → 走迁移路径导入。
  3. 导入全程可回滚：先备份现有数据，导入失败则恢复原状（复用既有「先备份后替换」模式）。
- **不兼容原版 TieZ**：用户明确说明无需兼容原版（名字已变，且第一版已做迁移）。

### 约束（破坏性操作）
导入恢复会**覆盖现有数据**，必须：
- 导入前**自动备份当前数据**到带时间戳目录
- 二次确认，明确提示"现有数据将被替换"
- 导入失败自动回滚
- 全程可恢复

## R9 MCP 功能：AI 可读写编辑导出剪贴板与标签

### 目标
通过 MCP 让 AI 能够：
- **读取**全部剪贴板历史
- **写入**新条目
- **编辑**既有条目（内容、备注、标签、置顶）
- **导出**数据
- **标签管理的全部操作**（标签 CRUD、条目打标签/移除标签、标签内条目 CRUD）

### 已具备的基础（勘察结论）
- `axum 0.8.8` **已是依赖**（含 `multipart`、`ws`、`macros`）→ 无需引入新 HTTP 框架
- `tokio`、`serde`、`serde_json`、`uuid`、`sha2` 均已在依赖中
- 项目已有 `file_transfer/web_ui.rs` 使用 axum 的先例可参考

### 验收条件
1. MCP 客户端可列出剪贴板历史（支持分页/筛选）。
2. 可新增条目、编辑内容与备注、删除条目。
3. 可读取/创建/重命名/删除标签，可为条目增删标签。
4. 可触发导出并取回文件路径。
5. **安全**：默认仅绑定本地回环；写操作需鉴权 token；提供**只读模式**开关。
6. 应用未启动时 MCP 不可用需有明确错误提示（或明确说明需应用运行）。

### 待确认（实现前）
MCP 传输方式与是否随应用启动，见 `docs/DEV-PLAN-v0.4.md` 的待决策项。

## R11 搜索剪贴板时不展开标签面板

### 现状（缺陷）
搜索剪贴板时，点击会**自动加入 `tag:` 筛选条件**，并展开标签面板，**遮挡视线**。

### 目标
搜索剪贴板时**不展开标签面板**，不自动插入 `tag:` 条件。

### 验收条件
1. 在剪贴板主页面搜索框输入关键词 → 标签面板保持收起状态。
2. 搜索不自动产生 `tag:` 前缀。
3. 用户**主动**通过标签筛选时，`tag:` 机制仍可正常工作（功能未被移除）。
4. 标签管理页面的搜索行为不受影响（如原本依赖展开）。

### 待确认
需精确定位「点击后自动加入 `tag:`」的触发代码，见 `docs/DEV-PLAN-v0.4.md`。

## 附录：用户需求原话

> 1，我电脑是主副双屏幕，我的鼠标焦点（在唤起我们的剪贴板窗口后）从一个屏幕一到另一个屏幕会导致我们这个窗口跟着跳变过去，还会自动设置为pin状态，这不应该而是应该保留在原始屏幕且另一个屏幕点击操作也不会自动关闭窗口（但不是pin状态只是我们另一个窗口的操作不影响我们的判断和窗口状态）
>
> 2，我们剪切板的标签管理页面中间的标签标题和标签组内的条目中间的分割要可以记忆就是用户拖动改变后要可以保持下次打开还能默认就是那个比例
>
> 3，标签管理里面的固定分组要可以删除以及随着对应功能关闭而隐藏，例如sensitive、密码，也就是所有分组都要可以删除，删了不会出错要保证
>
> 4，每个标签里面的条目都要是可编辑的，不论格式
>
> 5，这边有个bug就是有时候连续复制图片会被吞掉部分，还有复制链接自动会变成网站标题，导致下次粘贴不论是右键粘贴为纯文本还是正常单击全部都是标题纯文本，没看到链接自己了
>
> 6，标签条目里面还要可以加备注信息，并且可以在标签管理、剪切板主页面的条目里页面显示出来备注信息
>
> 7，标签管理点击粘贴出来的也要算作粘贴（复制）记录上剪切板主页面可以看到，作为最新条目
>
> 8.加入备份导出，和导入恢复功能 zip格式，包含全部数据，我要做到导入恢复就是完全恢复，且加一个规则就是之后的我们自己的版本开发始终要保持前向兼容，和后向兼容，（当然不会兼容原版的因为我们名字变了这个我们自己的版本第一版做了迁移了）
>
> 9，加入mcp功能让ai可以读取，写入，编辑，导出我们的剪切板所有历史、和进行标签管理条目的所有操作
>
> 10，剪切板主页面的剪切板记录所有条目都要可以编辑可以加一个编辑的按钮放到原来的分享按钮的左边
>
> 11，搜索剪切板时不要展开标签面板，就是点击后会自动加入帅选条件tag:那个东西不用，反而遮挡视线
