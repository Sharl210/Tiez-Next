## 这是什么

Tiez-Next 是一个以 Rust 为核心的剪贴板管理器：复制过的文字、富文本、图片、文件路径都会自动留存，随时检索、随时粘贴；可以用标签归类、给条目写备注，也可以通过 WebDAV 或 MQTT 在多台设备之间流转。

界面基于 Tauri 2，后端为 Rust，数据全部保存在本机。

## 核心功能

### 记录与检索
- **自动采集**：文字、富文本 (HTML)、图片、文件与目录路径都会记录；连续快速复制的多张图片不会丢失。
- **全局搜索**：按内容、来源应用、标签或日期检索。搜索时不会弹出标签面板遮挡结果。
- **顺序粘贴**：为高频办公场景设计的顺序拷贝 / 顺序粘贴工作流。
- **粘贴即置顶**：从标签管理里粘贴同样计入记录，并出现在主页面最新位置。

### 标签与条目
- **多色标签**：自定义颜色分类整理。
- **标签分组可自由增删**：包括内置分组在内都能删除，**删除分组不会连带删除条目**。
- **移动与复制到标签**：把一个条目移到另一个标签，或让它同时属于多个标签。
- **分组操作走右键菜单**：重命名与删除在标签上右键触发，不占用标签本身的显示空间。
- **任意条目可编辑**：文字类可直接改正文（富文本保存前会提示格式将转为纯文本）；图片、文件类可编辑备注。
- **条目备注**：给任意条目添加备注，标签管理与主页面均可查看。
- **表情管理**：内置 Emoji 表情库，支持快捷搜索与输入。
- **隐私脱敏**：识别身份证、手机号、邮箱等信息，预览时自动脱敏。

### 数据安全与容灾
- **自动容灾备份**：默认启用，每 30 分钟自动备份一次，最多保留 20 份（可调 1–200）。超量时删除最老的**未固定**备份。另有「启动时备份一次」的独立开关。
- **备份列表与固定**：在设置页可查看全部自动备份（时间精确到秒、大小、来源），右键可**固定**（固定后不会被轮换删除）、**删除**、**恢复**。
- **数据与程序分离**：数据目录始终在用户目录，**不在程序目录内**；覆盖升级与卸载都不会碰到数据。
- **迁移中心**：从旧版本迁入数据时手动指定路径，源目录全程只读、可反复验证。

### 窗口与外观
- **多屏友好**：在主副屏之间切换时窗口保持在原来的屏幕上，不会跟着鼠标跳；在另一块屏上点击也不会把窗口关掉或自动置顶。
- **贴边收纳**：支持自动停靠屏幕边缘，节省桌面空间且随时呼出。
- **主题**：支持 云母 / 亚克力 背景效果与暗黑模式，内置多款调优主题。
- **分栏比例记忆**：调整过标签管理的分栏比例后会被记住，下次打开直接就是那个比例。

### 数据安全
- **备份与恢复**：一键导出全部数据为 zip（数据库、附件、表情收藏、自定义背景），导入即完整恢复；导入前会自动备份当前数据，导入失败不破坏现有数据。
- **迁移中心**：集中管理旧数据目录，支持手动迁移与清理。迁移**只读取**来源目录、**不改动原数据**，可以反复执行；删除前会明确提示风险并自动备份。
- **拒绝外来包**：不导入其他应用（含旧版 TieZ）导出的备份，避免误操作。
- **前后向兼容**：备份包在后续版本之间保持可读，未知字段会被忽略而不是报错。

### 网络与同步
- **WebDAV 同步**：数据由你掌控，跨设备同步历史记录。
- **MQTT 协议**：轻量协议同步方案，适应不同网络环境。
- **局域网传输**：在局域网内传输文件与内容。
- **秒传验证码**：手机端收到的短信验证码，快速同步至当前设备。

### AI 接入（MCP）
内置 MCP（Model Context Protocol）服务，让 AI 客户端可以读取、搜索、编辑剪贴板历史与标签。

- **默认已开启**，默认允许写入，默认无需鉴权，默认端口 **23123**，默认**只监听本机**
- 端点：`http://127.0.0.1:23123/mcp`
- **支持局域网访问**：在设置里打开后服务改绑 `0.0.0.0`，同一网段的其他机器可以连接
- **可开启令牌校验**：打开后客户端需在请求头带上 `x-mcp-token`
- 读取内容**不做截断**，AI 拿到的是完整正文
- 通过 MCP 修改条目与在界面上操作**走同一套逻辑**，敏感标签的加密处理不会因入口不同而遗漏

> **关于默认值**：出厂的「免鉴权 + 仅本机」组合是安全的，因为只有本机进程能连上。**一旦开放局域网，请先打开令牌校验**——这两个开关相互独立，局域网本身不提供任何身份验证。

## 从源码构建

需要 Node.js 与 Rust 工具链。

```bash
npm install
npm run tauri:build:win     # 交叉编译出 Windows 安装包
```

在 Linux / WSL2 上交叉编译 Windows 产物需要 `cargo-xwin`；产物位于 `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`。

## 从旧版迁移

如果你之前用的是旧版（TieZ），**升级后不会自动搬运数据**——这是刻意的，避免在你不了解的情况下改动原目录。

请到「设置 → 数据与迁移」手动选择旧数据目录执行迁移。迁移只读取来源、不改动原数据，可以反复执行与反复验证。若旧版是便携版，数据在程序目录下的 `data/` 里。

## 相对原版（TieZ）的差异

本项目由 TieZ 演进而来。下面列出所有**行为差异**——包括新增能力、修复的问题，以及**移除的功能**。从原版升级前请先看这一节。

### 新增能力

| 能力 | 说明 |
| :--- | :--- |
| **标签条目移动 / 复制** | 把一个条目移到另一个标签，或让它同时属于多个标签。 |
| **条目备注** | 任意条目（含图片、文件）都能加备注，标签管理与主页面均可查看。 |
| **任意条目可编辑** | 文字类可直接改正文；图片、文件类可编辑备注。 |
| **AI 接入（MCP）** | 内置 MCP 服务，AI 客户端可读取、搜索、编辑剪贴板历史与标签。 |
| **备份与恢复** | 一键导出全部数据为 zip，导入即完整恢复；导入前自动备份。 |
| **迁移中心** | 集中管理旧数据目录，手动迁移与清理；支持从旧版及历史 Tiez-Next 迁移。 |
| **多屏友好** | 主副屏之间切换时窗口留在原屏，不跟随鼠标跳转，也不被自动置顶。 |
| **自动容灾备份** | 原版没有。定时 + 启动时自动备份，带备份列表、固定保护与轮换，且与手动导出的位置分离。 |
| **AI 接入能力更全** | 原版没有 MCP。本项目把界面能做的操作尽可能对等地开放给 AI 客户端，包括读写尚未落盘的条目。 |

### 修复的问题

| 问题 | 原版表现 | 现在 |
| :--- | :--- | :--- |
| **删除标签分组会连带删数据** | 删除分组时把组内条目一起删掉 | 只解除关联，**条目保留** |
| **连续复制图片被吞** | 快速连续复制多张图片时部分丢失 | 不再丢失 |
| **复制链接粘贴只剩标题** | 粘贴出来只剩网页标题，看不到链接 | 保留链接本身 |
| **搜索时标签面板遮挡** | 一搜索就展开标签面板挡住结果 | 不再弹出 |
| **内置分组无法删除** | 内置分组删了会自动重建 | 所有分组都可删，**删除后不会重建** |
| **标签管理粘贴不计入记录** | 从标签管理粘贴不产生记录 | 同样计入，并出现在主页面最新位置 |
| **分栏比例每次重置** | 调整后重开就恢复默认 | 记住比例，且**打开瞬间即为记忆值**（无跳变） |
| **升级时默认先卸载旧版** | 安装包默认选中「安装前卸载」，手快点下一步就会先跑卸载。 | 默认改为「直接覆盖」，保留选择页让你知道这是升级。 |

### 移除的功能

| 功能 | 原因 |
| :--- | :--- |
| **在线主题商店** | 它依赖原项目的服务器，本项目没有该服务；**继续兼容其主题包格式也非本项目方向**。因此整个商店（浏览、上传、评分、账号）连同入口一并移除。 |
| **官方网站入口** | 原官网属于原项目，本项目没有官网。 |
| **问题反馈入口** | 原入口指向原项目的邮箱，本项目没有对应渠道。 |

> **主题切换功能本身保留**：内置主题仍可正常切换使用。仅移除**在线商店**部分。
> 如果你此前选用过商店里的主题，升级后会自动回退到内置默认主题，界面不会异常。

### 不兼容原版备份包

备份包带有应用标识校验：**本项目不会导入原版 TieZ 导出的备份**（格式不同，强行导入可能损坏数据）。请使用原版自带的方式保留原数据，再用本项目的「迁移中心」搬运。

## 版本记录

### v0.5.3

> 这版的主线是**迁移终于能用了**，以及一个更本质的修正：**不再让界面显示"已设置"而实际没生效**。

**迁移：重新做了**

- **上一版的修复无效，原因是判定写错了。** v0.5.2 里我用来识别"文件被占用"的判断，在 Rust 里**永远不会成立**（`ErrorKind::Other` 根本不由标准库产生），所以提示文案换了、问题没修。已用能在真机命中的判据重写。
- **迁移改成了两阶段。** 点"迁移"时应用必然在运行，而它自己正占用着目标数据库——Windows 不允许改名已打开的文件。所以运行期只做"把数据复制到暂存"，**下次启动时**再完成接管。这样**不需要你退出应用、也不需要管理员权限**。
- **迁移过程有进度了**：当前在做什么、已处理多少项、已复制多少字节。不可计量的阶段会显示"不确定进度"，而不是假的 0%。
- **修掉一个会静默毁数据的问题**：如果迁移时选的是便携版的**外层目录**，附件路径会一条都匹配不上（现象是"记录都在、图片全打不开"）。现在会记归一化之后的数据目录。
- 迁移失败时，已让位的文件会**放回原位**并明确告知，不再出现"迁移失败但数据不见了"。

**不再骗你：设置真的生效了吗**

- **开机自启动**：以前是"先把开关点亮、失败只写进控制台"——所以**开关永远显示已开启，哪怕实际没写成功**。现在写完**立刻回读注册表核对**，并把读到的原文显示给你看；失败会明确报错。
  同时修掉一个误报：以前只要注册表里有旧版（TieZ）的残留项就报"已开启"，现在要**指向当前程序**才算。
- **游戏模式**：以前应用会**每次启动都默默把你的选择改回默认**。现在保留你的选择，明确告知"需要管理员权限才生效"，并提供一键提权重启。
- **Win+V 接管恢复了**。这个功能在之前某次上游改动里被误删了——后端六个命令全在，只是前端入口没了。现已恢复，并统一了前后端读写不一致的设置名。

**界面**

- 修复"打开设置页后，MCP 与自动容灾备份总是展开、其他都是收起"（分组的默认状态字典漏了两个键）。
- 弹窗不再半透明：遮罩叠着半透明弹窗，会透出被压暗的下层内容。现在弹窗不透明，遮罩也减轻了。

### v0.5.2

> 这版修的是 **v0.5.1 装到真机上才暴露的三个问题**。都是上一版没测出来的。

**修复**

- **迁移报「另一个程序正在使用此文件」**：在「迁移中心」里指定旧数据目录后，迁移报
  `os error 32`。原因是应用**自己正开着**目标数据目录里的那个空库，而迁移要给它改名让位
  —— Windows 不允许改名已打开的文件。现在会明确告诉你是 **Tiez-Next 自己**占用（不是别的
  软件），并给出可照做的下一步（从托盘退出应用后重试）。
  同时修掉一个更隐蔽的问题：**改名进行到一半失败时，已经改名的文件现在会被放回原位**
  （此前主库已被改名、副文件失败时会留在 `.unused-` 里，让你看到"迁移失败但数据不见了"）。
- **「备份列表」的刷新按钮一直在闪**：那其实是一个**无限刷新循环** —— 列表每渲染一次就会
  重新拉取一次数据，实测 300 毫秒内请求了 **206 次**、事件监听被反复注销重注册 **304 次**。
  已修好（现在各 1 次）。
- **「备份列表」的界面割裂感**：来源标签（"立即备份"/"启动备份"）长得太像按钮、工具栏
  按钮风格不统一、底部提示文字对比度过低（浅色主题下最低只有 **2.20**，远低于可读标准）、
  标题与路径行没有层级、关闭按钮过大。已按**保持现有配色与结构**的方式修正层级与一致性
  —— 六套主题下底部提示的对比度全部升到 **6.5 以上**，工具栏按钮逐字段一致。

**改进**

- 顺手修了内部验证台的一个缺陷：它一直**没有真正加载主题样式**，导致此前的"多主题验证"
  实际量到的都是同一组默认值。修复后才发现浅色主题下的对比度问题比原先看到的更严重。

### v0.5.1

> 这一版主要来自一次**真机安装后的用户反馈**。修复的重点是**数据安全**与**升级体验**。

**修复（数据安全）**

- **旧版数据迁不进来，界面却说「没有数据要迁移」**：判断「新版数据目录能否被旧数据接管」的判据要求设置项与全新安装**逐键完全相等**，而应用自己会写设置——最平凡的是**窗口尺寸**（拖动一下窗口就会写入）。于是只要调整过窗口大小，迁移就**永远**被拒绝。已改为只看**有无用户数据**（剪贴板记录、自建标签）。**旧版本这次能正常迁入了。**
- **数据目录可能落在程序目录内部**：原本若程序目录下存在 `data/` 文件夹，数据就会写在那里。而卸载会删除程序目录 —— **等于卸载即删数据**。现在数据一律放在用户目录（与安装目录**互不包含**），升级与卸载都不会碰到它。
- **卸载器会递归删除整个安装目录且不做任何检查**：加了三条判定（目录非空且像安装目录、含本应用安装标记、**不含数据痕迹**）。命中数据痕迹时**保留目录并提示**，不静默删除。
- **MQTT 密码等凭据会随云同步双向外流**：云同步的排除清单只列了 5 个敏感设置里的 2 个，于是 **MQTT 密码、MQTT 用户名、AI 配置**会被**上传到云端**、也会被远端快照**写回本机**。已改为与加密侧**共用同一判据**，并遍历全部敏感键做测试。
- **AI 接口可以自己给自己提权**：新增的设置写入工具原先允许写 `mcp.*` —— 那里面有「是否免鉴权」「是否允许局域网」，等于让 AI 落库一份「免鉴权 + 局域网可达」。现在**硬拒**这些键（用户仍可在界面改）。

**修复（升级体验）**

- **覆盖升级默认「先卸载再安装」**：安装包遇到已装版本时会弹一个选择页，**默认选中「安装前卸载」**。手快点了下一步就会先跑卸载程序。现在**默认选中「直接覆盖」**，同时**保留该选择页**让你知道这是升级而非重装。（应用内自动更新本来就是覆盖式的，这一版修的是**手动双击安装包**这条路。）
- **「添加/删除程序」里残留一条旧版名字的卸载项**：原版卸载后留下的条目我们从未清理（我们清的是另一种注册表键）。结果列表里新旧两条并列，点到旧的那条会跑起来**原版卸载器**。现在安装时与启动时都会清理它。
- **标签分组右键菜单**新增重命名与删除（此前只能改颜色）。

**新增**

- **自动容灾备份**：默认开箱启用，每 **30 分钟**自动备份一次，最多保留 **20 份**（可调 1–200），超量时自动删除**最老的未固定**备份。另有「软件启动时备份一次」的独立开关（不受定时开关影响）。
  - 设置页有独立的「自动容灾备份」分组，内含**备份列表**：每份显示时间（**精确到秒**）、大小、来源。
  - **右键**可**固定**（固定后不会被轮换删除，类似行车记录仪的锁定）、**删除**、**恢复**（后两者都需要二次确认）。
  - **固定的份数上限是「最大留存数 − 1」**，保留一个位置给轮换。达到上限时会明确告诉你当前的数字与原因，而不是静默失败。
  - 备份是**压缩包**，与手动导出的位置不同（自动备份由应用保管、参与轮换；手动导出由你选路径、不受份数限制）。
- **AI 接口（MCP）能力大幅补齐：19 → 37 个工具**。最重要的一个是：**它原先读不到「还没落盘的剪贴板条目」** —— 在默认设置下，新复制的内容先进内存，而接口只读数据库，于是**AI 看到的条目和你在屏幕上看到的完全不相交**，且不报错、只返回空列表。现在读写都覆盖内存层。另新增设置读写、备份导入、剪贴板写入与粘贴、表情收藏、粘贴队列、数据迁移等工具。

**改进**

- **备份包体积与耗时**：原先的压缩策略**方向是反的** —— 唯一真正值得压缩的（数据库，里面是文本，压缩率约 0.23）被跳过不压，而**已经压缩过的图片**却拿去压。结果是**整包比原数据还大 1.4%**，小图标甚至**膨胀 33%**。改为按「内容是否还可压」分流后：**体积省 11.8%、耗时快 3.9 倍**。
- **补齐 38 处「用了从未定义的样式变量」**：这类问题**不报错、不警告、构建通过**，只是该有的边框/背景/阴影**静默消失**。最明显的一处是数字输入框**完全没有边框**。已全部修复，并加了一条会在构建时自动拦截的检查。
- **修掉一条测不出问题的测试**：它断言的是「改过设置就不能算空库」——**把上面第一个缺陷写成了正确行为**。测试全绿，功能全坏。已改为断言正确行为。
- **补齐 MCP 参数校验**：原先只校验必填与顶层类型，现在覆盖取值范围、枚举、数组长度与元素类型；并补上 3 个「能用但文档里查不到」的参数。

**移除**

- 删除了一处从不被调用的空壳函数（它让人误以为界面与 AI 接口共用同一条清空历史的路径）。

### v0.5.0

**新增**

- **标签分组排序**：可按名称（`A-Z` / `Z-A`）、最近使用、条目数、内容体积排序，每个维度都有正反两个方向；默认按名称，选择会被记住。
- **图标全部更换**：托盘、任务栏、安装器与 README 的图标原先都是原版的（托盘是个字母「Z」）。现在换成不带文字的剪贴板图形标，16×16 下仍可辨认。
- **MCP 默认开箱可用**：默认开启、默认允许写入、默认免鉴权、默认端口 `23123`，默认仅监听本机。

**修复**

- **迁移可能把无关文件搬进数据目录**：选中一个「装着旧数据的目录」而非数据目录本身时，整个目录树会被复制进应用数据目录，数据落在应用不读的位置，界面却提示「迁移完成」。最坏情况会把私钥、合同这类文件一并搬进去。现在会在复制前拦下并给出准确的下一步提示（「请往下再选一层」）。
- **「移动到标签 / 复制到标签」看不到已有标签**：从主列表打开时目标候选是空的，只能手打标签名。
- **标签分组右键菜单的 5 条测试是空断言**：它们在「菜单根本打不开」的实现上也会通过，等于没测。已补存在性前置。
- **MCP 开关改动不即时生效**：关闭写权限、打开令牌校验原先要等重启才起作用。
- **主题商店残留**：已选过商店主题的用户升级后可能拿到一个没有任何样式对应的主题 id。

**安全加固**

- **备份路径护栏下沉**：原先只有界面侧校验备份输出路径，MCP 可绕过。指向数据目录内的 `clipboard.db` 会**截断正在使用的数据库**。护栏已移到所有导出路径的唯一汇聚点。
- **收窄应用可打开的外部链接**：`opener:default` 权限自带 `http://*` / `https://*` 通配范围，与白名单是「或」关系，等于白名单失效。已改为只保留显式白名单。
- **云同步不再携带 MCP 设置**：包括访问令牌与「是否允许局域网访问」等开关，避免被篡改的远端快照在本机种下危险配置。
- **移除上游公告上报**：原会每天向原项目服务器发送带机器标识的请求。

**移除**

- **在线主题商店**（含入口与文案）。理由见上文「移除的功能」。

## 维护约定

**每个版本的功能变化，都必须同步写进本 README。** 具体地：

1. 新增功能 → 写进「核心功能」对应小节，并在「相对原版（TieZ）的差异 → 新增能力」中补一行。
2. 修复问题 → 在「差异 → 修复的问题」中补一行（若该问题原版也存在）。
3. 移除功能 → 必须在「差异 → 移除的功能」中记录，并说明原因。**移除项不能只字不提**——升级的用户需要知道什么东西不见了。
4. 行为变更（含默认值、交互方式变化）→ 同样记入差异表。
5. 每次发版前检查本节是否与代码一致；**README 与实际行为不符视为缺陷**。

这条约定的目的：让"这个版本和原版到底有什么不同"始终有一个**单一、可信、随版本更新**的答案，而不是散落在提交记录里。

### 另有一份给改代码的人的文档

上面这条约定管的是**产品层面**的记录。另有一份 `docs/MAINTENANCE-LIABILITIES.md`，
管的是**维护层面**的记录：

> 过去某个决定会在**之后持续影响维护工作**——某段看起来奇怪的代码其实是故意的、
> 某个旧名字删掉会损坏用户数据、某个文件已经和上游分叉了需要手动同步。

那份文档每条都写清「做了什么 / 为什么 / 之后要注意什么 / 什么时候可以撤销」，
**可独立阅读，不依赖任何其它资料**。准备改动某个模块前，建议先在里面搜一下。

它同样是**持续维护**的：任何会产生长期负担的决定，都应当记进去。

另有一份 **`维护文档.md`**（仓库根目录）：那是**决策流水账**——按时间追加、只增不改，
记录「谁在何时做了什么决定、影响什么、被谁替代」，带索引与替代链，可 grep 渐进读取。
两份文档分工不同：`MAINTENANCE-LIABILITIES.md` 按主题回答「这段代码为什么不能改」，
`维护文档.md` 按时间追溯「这个决定是怎么演变的」。
