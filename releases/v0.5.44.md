# v0.5.44 — 链接一律变成网址本身

这一版修的是"转换了还是没变"这件事。上一版改了一半，仍然不对：**转换出来的还是标题文字，不是网址。**

## 问题出在哪

上一版只在一个很窄的条件下才把链接换成网址：**整条内容恰好就是一个链接**。除此之外都保留原文。你的要求是**所有**超链接都换成网址本身，所以那个条件太窄了。

更关键的是第二个原因：**主界面上那个「转换为纯文本」按钮读的是编辑器里显示的文字**。屏幕上一条链接显示的是带下划线的「T750 变更单」，那么"读屏幕文字"读到的就只能是「T750 变更单」，网址（藏在 `href` 里）根本不在那串文字里。上一版我修好了标签管理页那个按钮，漏了主界面这个。

于是你点按钮 → 拿到的还是标题 → 看起来"改了没用"。

## 现在的规则

**只要有超链接，就换成网址本身。** 不管它在正文的什么位置、是不是唯一一个。

| 输入（界面上看到的） | 转换/纯文本粘贴后 |
|---|---|
| 一条链接：`T750 变更单`（指向 `http://…/176116`） | `http://…/176116` |
| 正文里夹带：`详见 T750 变更单 里的说明` | `详见 http://…/176116 里的说明` |
| 两个链接 | 两个各自的网址 |
| `javascript:` / `data:` 这类点不动的 | 保持原样 |

**富文本形态完全不受影响**：富文本粘贴、列表渲染仍然是原来带下划线的样子。只有"纯文本形态"才换成网址。

## 顺带修好的几处漏网

同一个规则原先散落在好几个地方各自判断，于是漏了几条出口 —— 从这些地方出去的也都还是标题：

- **顺序粘贴**（队列粘贴热键）：直接取库里存的正文，没走转换规则。
- **MCP / AI 读取条目**：把库里原始正文直接交给 AI，AI 看到的是标题不是网址。
- **云同步**：把本机早先存下的标题原样搬到另一台设备。
- **标签管理「复制选中」**：拼接的是库里的旧正文。
- **界面刷新事件**：有 6 处直接把条目实体推给界面、绕过转换。

现在这些统一收敛到一个入口，规则只写一遍。

## 你已经转换过的那些条目也能救回来

这是你"还是不对"的另一个原因。

早先点过「转换为纯文本」的条目，类型已经变成纯文本，**之后就不再参与富文本的那套转换**了 —— 所以里面存的标题会一直留着。好在转换时原始 HTML 是**保留**的（没有清空），网址还在里面，可以恢复。

现在读取和粘贴时会自动把它们修好。但有一条保护：**如果你后来手动改过那条的正文，就不动它** —— 判断方式是"存的正文是不是恰好等于那份 HTML 的显示文字"，相等说明它只是当年转换留下的旧结果，可以安全替换；不等说明是你自己写的，保持原样。

## 独立复审发现并修好的另外几处

我派了一个专门找茬的复核者去查"这三件事是不是真的做到了"。它找出了几个我自己没注意到的问题，都已修好：

1. **MCP（给 AI 用的接口）的「转换为纯文本」根本没生效**：界面按钮传的是"清空格式"，而 MCP 那条传的是"保留格式"，导致同一个功能两个结果 —— 走 MCP 转换后条目**仍然是富文本类型**，界面里照旧带下划线，只有 AI 拿到的返回值是网址。现在两边统一。

2. **已转换过的存量条目里，"链接紧贴正文"的那批修不回来**：恢复逻辑原先要求存的正文与旧结果**完全**一致，但旧按钮读屏幕文字时链接紧贴正文不补空格、后端旧逻辑却会补空格，于是 `详见标签说明` 与 `详见 标签 说明` 差一个空格就判定为"不是旧结果"、放弃恢复。现在按"忽略空白"比对，这批也能救回来。**同时保持**：你真正手写过的正文不会被覆盖（文字本身不同就不动）。

3. **同一个文件，界面按钮和后端粘贴的行结构不一致**：两个相邻段落，后端给的是空行分隔、前端给的是单换行；表格两格在界面上会粘成"项目值"。现在前端与后端统一（后端是粘贴那条路的权威）。

4. **不加引号的链接抓不到**：`<a href=http://…>看这里</a>`（没写引号）后端认不出，而界面能认出。现在两边都认。

5. **云同步接收侧不校正**：如果另一台设备还是旧版本（正文里存的是标题），同步过来时标签会被原样落到本机。现在以本机规则重新算一遍。

另外核对了三处**看似有问题、实际正确**的地方，没有改动：

- 右键之后的纯文本通道确实会**清空剪贴板**再写纯文本，所以不会残留富文本格式（这点很关键，否则右键拿到的可能还是带格式的）。这一条我追到了底层库的实现确认。
- 「打开内容」对富文本写的是 `.html` 文件、用浏览器渲染 —— 那是**富文本形态**，显示带下划线的链接是对的，不该改成网址。
- 数字快速粘贴（修饰键+数字）仍然只对置顶条目生效。这是**有意的设计**，不是这次那个 bug：它的语义是"固定项快捷键"，如果槽位随列表浮动（新复制一条就全部移位），这个功能就没有意义了。设置里的说明也写的是"固定项"。**这一条属于产品取舍**，如果你希望改成"前 10 条无论是否置顶"，告诉我。
