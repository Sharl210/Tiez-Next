# 历次发布说明存档

本目录存放每次发布时**面向用户**的版本说明原文（GitHub Releases 页面的正文）。

## 为什么单独存一份

GitHub Releases 是这些说明的**权威出处**，但它不在仓库里 —— 无法随代码一起 diff、
无法在离线环境查阅，也无法在改写前先留底。

本目录解决三件事：

1. **留底** —— 改写已发布的说明前，先在这里保存原文（改写是不可逆的对外动作）
2. **可追溯** —— 发布说明与代码在同一棵树里，能对照当版实际改了什么
3. **作为体例范本** —— 新版本照这里最好的那篇写

## 阅读顺序

- 想看**某个版本改了什么**：看 `vX.Y.Z.md`
- 想知道**发布说明该怎么写**：见仓库根 `维护文档.md` 的 `MD-0024`
- 想看**产品功能的完整清单**：见 `README.md` 的「核心功能」与「相对原版差异」

## 体例

以 `v0.3.4.md` 为范本（它是本项目对外口吻做得最好的一篇 —— 无测试表格、无第一人称、
无内部符号，且有「安装」与「说明」两节）。

每篇至少包含：

- 一句话说明本版主线
- 面向用户的变化（**说清"我要做什么"**）
- **`### 安装`** —— 下载哪个文件（每篇 Release 下有 `setup.exe` 与 `sig` 两个附件）
- **`### 说明`** —— 未实机验证的风险披露

## 注意

本目录是**存档与范本**，不是对外发布渠道。**发布说明的权威版本在 GitHub Releases 页面。**
