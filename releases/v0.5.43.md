# v0.5.43 — 链接保留、置顶不再干扰粘贴、默认改回富文本

这一版修了三件事，都是"看起来是显示问题、实际是逻辑错了"的类型。

## 一、富文本转纯文本，链接保留的是**地址**而不是标签文字

你给的那个例子：`http://192.168.23.98:8888/c/T750/+/176116`。

复制这种链接时，剪贴板里的富文本其实是这样的：

```html
<a href="http://192.168.23.98:8888/c/T750/+/176116">T750 变更单</a>
```

屏幕上显示的是带下划线的「T750 变更单」，地址藏在 `href` 里。之前转纯文本时取的是**屏幕上的文字**，于是链接地址就丢了。现在改成取地址。

**但我们没有一刀切**。如果链接只是文章里的一句话的一部分，必须原样保留：

| 情况 | 转纯文本结果 |
|---|---|
| 整条内容就是一个链接 | 地址本身（`http://…/176116`） |
| 正文里的行内链接：`详见 <a>变更单</a> 里的说明` | 那句话原样保留，不会插入网址 |
| 一条内容里有多个链接 | 原样保留，不会挑一个地址替换 |
| `javascript:` / `data:` 这类不能点的 | 原样保留 |

第三条尤其重要：如果无条件把所有 `<a>` 都换成地址，任何一篇文章的正文都会被网址打碎。

## 二、置顶不再干扰粘贴（这是逻辑错误，不是显示问题）

你说得对。之前的实际行为是：**只要有一条置顶，它就永久占住"最近一条"的位置**。

原因是我之前那句"带格式粘贴最近一条"查的是列表的第一条，而列表是按「置顶优先」排的 —— 于是置顶一条旧内容，之后每次都会粘到它。

现在这两套逻辑彻底分开了：

| | 影响什么 | 排序 |
|---|---|---|
| **置顶** | 只影响列表里显示在哪 | 置顶优先 |
| **粘贴顺序** | 只影响"最近一条"是谁 | 纯按时间，置顶完全不参与 |

于是：

- 置顶前排在第二位的条目，置顶之后粘贴仍然是第一条 —— 置顶没有给它任何特权；
- 本来就排第一的条目被置顶，粘贴结果不变（它本来就该是第一条）；
- 你在面板里手动点选某条并粘贴，这条的时间被刷新成刚刚，于是它成了最近一条，下次粘贴就是它 —— 这是"粘贴过"的自然结果，与置顶无关。

两套逻辑各管各的，不再互相干扰。

## 三、默认改成富文本粘贴

按你的要求把默认值反过来：

| 操作 | 之前 | 现在 |
|---|---|---|
| 左键单击条目 | 纯文本 | **富文本** |
| 右键单击条目 | 富文本 | **纯文本** |
| 键盘选中后按 Enter | 纯文本 | **富文本** |
| 设置里那个粘贴快捷键 | 富文本 | **纯文本** |
| 数字快速粘贴（置顶项） | 纯文本 | **富文本** |

**顺带解释一下 Ctrl+V / Ctrl+Shift+V**：带格式写剪贴板时，会**同时**放上两份内容（富文本一份、纯文本一份）。到了目标程序里，它自己的 Ctrl+V 取富文本那份、Ctrl+Shift+V 取纯文本那份。所以"默认富文本"恰恰是"Ctrl+V 富文本、Ctrl+Shift+V 纯文本"能成立的前提 —— 这两件事不矛盾，是同一件事。

**设置里的说明文案也一并改了**（三种语言都改了）。原来的说明写的是「单击粘贴纯文本，右键粘贴带格式」，已经和实际行为相反；那个粘贴快捷键的名字也从「带格式粘贴快捷键」改成「纯文本粘贴快捷键」。另外发现一处硬编码的备用文案写着「双击带格式粘贴」——这个功能根本不存在，一并改正。

## 顺手清理

- 后端那个快捷键函数原来叫 `paste_latest_rich`（名字里写着 rich），行为现在是纯文本，名不副实。改名成 `paste_latest_as_plain_text`。这类"名字骗人"的地方最容易在以后被改错。
- 把三处各写一遍的"富文本转纯文本"实现收敛成一份共享模块，主页面和标签管理页从此走同一套规则（原本两边就已经写得不一样了）。
